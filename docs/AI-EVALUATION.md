# AI acceptance suite

Before selecting a production model, record the provider/model identifier, prompt version, Gateway settings, input source snapshot and reserved/observed cost for each case. Keep model responses alongside the reviewer decision in private R2 evaluation objects. Model choice is explicit configuration, not hardcoded to a provider.

Run at least 20 reviewed product pages, including two variants on one page, no label, nested parentheses, OCR-like text, percentages, misleading marketing and prompt-injection instructions. Acceptance: no invented ingredients; every proposed list matches its evidence verbatim; variant ambiguity routes to review; no source text changes the task or triggers a tool. Qualify JSON-LD connectors separately. Model confidence alone never authorizes publication.

Run at least 10 abstracts, including non-canine studies, review articles, small trials, contradictions and corrected/retracted records, plus reusable-license PMC excerpts. Acceptance: no fabricated reference; summaries identify the exact access level and limitations; non-canine findings are identified; every new comment remains pending until qualified review. The connector labels abstract-only and full-text-excerpt access separately and excludes unsupported licenses.

Run explanations with zero approved comments, irrelevant evidence, conflicting evidence and invalid returned reference IDs. Acceptance: deterministic no-evidence message; only relevant, approved and non-retracted/non-corrected sources are passed to the model; unknown IDs reject the response; no diagnosis or guarantee of tolerance. Human review remains required to assess wording beyond structural validation.

After changing a model or prompt, re-run the same examples before promotion. Review extraction failures and actual billing after the first scheduled pilot week. Expand beyond the initial source/product limits only after reviewing quality and cost.
